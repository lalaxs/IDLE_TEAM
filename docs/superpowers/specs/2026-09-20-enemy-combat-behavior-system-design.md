# 敌人战斗差异化系统设计

- 版本：1.1
- 日期：2026-09-20
- 状态：可开发规格
- 适用范围：10 章 × 12 关、五波小怪 + 1 波 Boss 的自动战斗
- 首个垂直切片：第一章 E01～E12、B04/B08/B12
- 关联内容：`src/content/enemies.ts`、`src/simulation/WaveSystem.ts`、`src/simulation/BattleSimulation.ts`、`src/simulation/types.ts`
- 全量内容：[十章敌人战斗内容矩阵](2026-09-20-enemy-combat-content-matrix.md)

## 0. 结论

敌人差异采用五层结构：

```text
基础属性差异
  + 一个职责行为（普通怪）
  + 一个可读机制（精英）
  + 区域机制（普通怪池共享语义）
  + 招牌主动 + 一个阶段被动（区域 Boss）
```

普通怪不做英雄级技能。玩家通过射程、攻速、移速、血量、防御、元素和一个轻行为识别普通怪；精英负责考验一次阵容处理顺序；Boss 负责形成关卡记忆点。行为、效果、目标选择和触发器全部配置化，运行时不按 `enemyId` 写分支。

本规格的第一章数值建立在现有敌人底座上：E01～E12 与 B04/B08/B12 的生命、攻击、防御、攻击间隔、射程、移速和元素不在本规格中重做，行为只补充战斗职责。后续平衡仍沿用现有敌人数值成长与软护甲公式。

## 1. 现状与明确问题

### 1.1 当前内容模型

`src/content/enemies.ts` 的 `EnemyDefinition` 当前包含：

- `maxHp`、`attack`、`defense`；
- `attackIntervalMs`、`attackMode`、`attackRange`、`moveSpeed`；
- `kind`（normal / elite / boss）；
- `damageElement`。

这些字段足以表达均衡、快攻、高防、近战和远程，但没有表达职责行为、触发条件、目标策略或技能表现。

### 1.2 当前运行时行为

- `WaveSystem.createEnemyUnits` 给普通怪和精英的 `skillTriggerMs` 设为无穷大，只有 Boss 自动进入技能计时。
- `BattleSimulation.basicAttack` 让敌人统一使用 `frontmostEnemy`，普通怪没有独立目标策略。
- 精英在每 4 次普攻后统一获得 `damageReduction 20% / 2 秒`，E04、E08、E12 只是换外观和数值。
- Boss 技能在 `BattleSimulation.castBossSkill` 中按 `B04`、`B08`、`B12` 等 ID 分支；当前后续 Boss 大量回落到同一套默认技能。
- Boss 技能会在可施放时直接结算，现有 `skill:started` / `skill:resolved` 事件没有统一的敌方蓄力配置。
- `StatusKind` 已覆盖 `stun`、`slow`、`haste`、`damageReduction`、`armorBreak`、`vulnerability`；单位已有 `shield`、`periodicEffects`、`skillPrepareMs`、`skillCastDurationMs`、`skillCastId` 等字段。
- `WaveSystem` 已落地五个小怪遭遇，数量节奏为 `3 / 4 / 5 / 5 / 6`，Boss 另有 `0 / 1 / 1 / 2` 名随从。

### 1.3 玩家实际感受的根因

1. “远程 / 近战”只改变攻击距离，不能改变处理优先级。
2. 普通怪只普攻，击杀顺序、阵型和英雄目标策略几乎没有决策差异。
3. 精英的统一减伤没有告诉玩家“这个精英为什么危险”，也没有让区域主题落到战斗。
4. Boss 技能按 ID 硬编码，内容量增长会让每章都复制 `if/else`，并且同一 Boss 在普通关、区域终点、高难度之间无法复用同一份数据。
5. 当前自动战斗没有明确的敌方目标选择契约，未来加入后排攻击、援护或范围效果时容易出现看不懂、不可复现的结果。

## 2. 设计原则与不做项

### 2.1 设计原则

1. **先职责、后数值。** 每个怪物必须能用一句话说出“它要求玩家先处理什么”。
2. **一个怪物一个读点。** 普通怪最多一个轻行为；精英最多一个可读机制；第一章 Boss 每只一个主动和一个阶段被动。
3. **区域先教概念，章节再组合。** 每章新增一个主机制，第四关、区域终点和章节终点只提高组合密度或数值，不突然引入四种新效果。
4. **自动战斗也要公平。** 所有影响胜负的敌方行为都必须有稳定目标规则、可观察提示和固定上限。
5. **技能是内容数据。** 触发、目标、效果、数值和表现从数据中读取，不能让 `BattleSimulation` 知道具体怪物 ID。
6. **效果复用优先。** 第一章只复用现有伤害、状态、护盾和目标选择；周期伤害/治疗等能力按章节在后续阶段接入。
7. **数值承担成长，行为承担识别。** 敌人血量、攻击和防御继续沿用现有成长曲线，机制不用于掩盖数值失衡。

### 2.2 不做项

- 不为普通怪制作独立英雄式技能栏、复杂连招或多阶段 AI。
- 不引入需要玩家实时走位、躲避、打断或点击目标的技能。
- 不依赖沉默、驱散、不可回复或长时间群控来制造难度。
- 不引入英雄当前阵容无法稳定克制的命中率、免疫、反伤锁死或永久无敌。
- 不为每个怪物建立独立运行时类，不复制一份 `castBossSkill`。
- 不把美术造型、攻击距离或元素自动推断成行为；行为必须显式配置。
- 不照搬 TBH 的绝对数值、技能名称或界面。TBH 只作为“普通怪保持轻量、Boss 随难度增加技能位”的结构参考。

## 3. 复杂度预算

### 3.1 敌人等级预算

| 敌人槽位 | 数值职责 | 行为预算 | 触发上限 | 第一章规则 |
|---|---|---|---|---|
| N1 基础普通怪 | 一项主属性明显，其他属性接近区域基准 | 0 个行为，纯普攻 | — | E01、E05、E09 |
| N2 速度/压制普通怪 | 攻速、移速或目标策略明显 | 1 个轻行为 | 每 3～5 次普攻或首次触发 | E02、E06、E07、E10 |
| N3 功能普通怪 | 血量、防御或元素支持职责 | 0～1 个轻行为 | 每 4～6 次普攻或一次半血触发 | E03 用一次护壳；E11 仅靠高防形成职责 |
| E1 精英 | 约 2.2～3.0 倍普通怪生命预算；拥有清晰外轮廓 | 1 个机制包 | 每 4～6 次普攻或 6～9 秒 | E04、E08、E12 |
| B1 区域 Boss | 独立生命、攻击和场景体量 | 1 个主动 + 1 个阶段被动 | 主动 4.5～7 秒；阶段一次 | B04、B08、B12 |

“行为包”可以同时包含触发、目标和一个主效果。一次主动内的“伤害 + 与该伤害绑定的慢速”算一个效果包，不算两个技能；不得借此绕过复杂度上限。

### 3.2 强度预算

所有比例以单位 `attack` 或 `maxHp` 为基准，先经过现有元素和软护甲计算。

| 项目 | 普通怪 | 精英 | Boss |
|---|---:|---:|---:|
| 单次额外伤害 | `0.15～0.45 × attack` | `0.40～0.90 × attack` | `0.90～1.60 × attack` |
| 单个目标一次结算总伤害上限 | 不超过 `1.35 × attack` | 不超过 `1.60 × attack` | 不超过 `1.60 × attack` |
| 减伤强度 | `10%～20%`，最多 3 秒 | `15%～25%`，最多 3 秒 | `15%～30%`，阶段被动可永久但只触发一次 |
| 护盾 | `8%～15% maxHp` | `10%～18% maxHp` | `12%～25% maxHp` |
| 慢速 | `10%～25%`，最多 2.5 秒 | `15%～30%`，最多 3 秒 | `15%～35%`，最多 3 秒 |
| 单体眩晕 | 不超过 0.6 秒 | 不超过 0.8 秒 | 不超过 0.8 秒 |
| 群体控制 | 普通怪禁用 | 精英禁用 | 只允许群体慢速，不允许群体眩晕 |

同一个单位的多个来源按现有 `StatusSystem` 的同类最大值规则处理。单个怪物不能同时提供减伤、护盾和控制三个独立效果。

## 4. 可复用行为、效果与触发器目录

### 4.1 触发器目录

| 触发器 | 参数 | 适用 | 规则 |
|---|---|---|---|
| `onEnterCombat` | `delayMs` | N2、E1、B1 | 只触发一次；用于首击强化或首次护盾 |
| `onBasicAttackCount` | `count` | N2、E1 | 命中后计数；未命中不消耗计数；计数在波次切换时重置 |
| `onTimer` | `initialMs`、`cooldownMs` | E1、B1 | 从单位进入战斗状态开始计时；施法中暂停下一次计时 |
| `onHpBelow` | `threshold`、`once` | N3、B1 | 只在从阈值上方跨入时触发；第一章只允许一个阈值 |
| `onAllyHurt` | `cooldownMs`、`minHpPct` | 后续 E1/B1 | P1；同一伤害事件只触发一次，不连锁触发 |
| `onAllyDeath` | `cooldownMs` | 后续 B1 | P2；第一章不使用召唤或复活 |

`onAllyHurt` 与 `onAllyDeath` 属于后续阶段，第一章垂直切片不需要新增事件监听。

### 4.2 目标选择目录

| 目标策略 | 当前或计划状态 | 语义 |
|---|---|---|
| `frontmostEnemy` | 当前可复用；P0 补稳定并列排序 | 从来源单位视角选择对方阵营最靠前的存活单位；敌人使用时即前排英雄 |
| `nearestEnemy` | 当前可复用；P0 补稳定并列排序 | 从来源单位视角选择距离最近的对方单位 |
| `lowestHpEnemy` | 当前可复用；P0 补稳定并列排序 | 从来源单位视角选择生命比例最低的对方单位 |
| `frontmostEnemies(n)` | P0 接线 | 按来源单位视角从前到后取最多 `n` 名对方单位；已有 Boss 多目标逻辑可抽成通用选择器 |
| `lowestHpAlly` | 当前可复用 | 敌方阵营中生命比例最低且未满血的单位 |
| `self` | 当前可复用 | 施法者自身 |
| `lowestHpAllyOrSelf` | P1 | 有受伤友军时优先友军，否则自身 |

这些名称沿用当前 `TargetStrategy` 的“相对来源单位”语义，避免再造一组 `Hero` 专用策略。最低生命按 `hp / maxHp`、最近目标按距离、前排目标按阵营方向的 `x` 排序；所有并列情况最后都按稳定单位 `id` 排序。技能目标在开始时锁定，解析期间死亡的目标从结算列表移除，不重新随机换目标。

### 4.3 效果目录

第一章允许使用以下现有效果：

| 效果 | 数据字段 | 第一章用途 | 上限 |
|---|---|---|---:|
| `damage` | `powerPct`、`element` | 普攻追加、Boss 范围攻击 | 见强度预算 |
| `slow` | `magnitude`、`durationMs` | E06、E10、B04、B12 | `0.35 / 3000ms` |
| `stun` | `durationMs` | E08 单体短控 | `800ms` |
| `haste` | `magnitude`、`durationMs` | Boss 阶段被动 | `0.25`；阶段永久仅一次 |
| `damageReduction` | `magnitude`、`durationMs` | E03、E04、B08 | `0.30`；单次 3000ms |
| `armorBreak` | `magnitude`、`durationMs` | P1 敌方破甲 | 第一章不赋予敌人 |
| `vulnerability` | `magnitude`、`durationMs` | P1 第二章易伤 | 第一章不赋予敌人 |
| `shield` | `amountPctMaxHp` | E12 | `0.25 maxHp` |
| `periodicDamage` | `powerPct`、`intervalMs`、`ticks` | 第 5 章起按章节解锁 | P2；第一章不使用 |
| `periodicHeal` | 同上 | 第 5 章起按章节解锁 | P2；第一章不使用 |

第一章不新增 `silence`、`dispel`、`fear`、`root`、`invulnerability`、`summon`、`revive`、`reflect` 等效果。`突进`在第一章只通过已有移速、攻击距离和首击倍率表达，不实现需要实时躲避的位移技能。

### 4.4 触发处理顺序

固定为：

```text
advanceStatuses
  → tick periodic effects
  → 检查单位存活与眩晕
  → 更新普攻/行为计时
  → 锁定目标
  → 读取行为配置并开始施法或结算
  → 伤害、状态、护盾、治疗
  → 处理死亡与击杀进度
```

一个行为结算产生的状态只影响后续事件，不回溯修改同一事件已结算的伤害。行为触发与普通攻击使用同一个 `SeededRandom`，不额外引入不可重放随机源。

## 5. 自动战斗公平性规则

1. **敌人默认目标**：沿用当前 `frontmostEnemy` 的来源相对语义；敌人使用时选择前排英雄，保证前排英雄拥有保护后排的真实价值。
2. **后排威胁**：只有显式配置 `lowestHpEnemy` 的敌人才可越过前排；第一章只给 E07 使用，且只改变普攻目标，不叠加高额爆发。E07 入场时锁定一次目标，目标死亡后才重选，移动和普攻必须共用同一个 `targetId`，避免追逐目标与实际攻击目标不一致。
3. **技能目标锁定**：技能开始时取一次目标快照；目标死亡时跳过，不转移到随机单位。
4. **范围上限**：普通怪 1 个目标，精英 1 个目标，Boss 第一章最多 3 个目标；范围目标必须按前后顺序稳定选取。
5. **施法预警**：精英和 Boss 主动技能必须至少有 `600～1200ms` 的准备时间。准备期间单位不普攻；技能不因普通移动改变目标。若施法者死亡或被眩晕，技能取消。
6. **眩晕上限**：第一章只有 E08 使用单体短眩晕；Boss 使用慢速，不形成群体眩晕链。任意英雄被敌方控制的连续时间不得超过 `800ms`。
7. **波次间重置**：普通怪行为计数、Boss 主动冷却和阶段状态都按“每次新生成单位”初始化；英雄状态按现有规则处理。
8. **可重放**：同一 `stage + seed + party + level + gear` 必须生成相同编队、相同目标顺序和相同触发结果。
9. **离线一致**：行为不能依赖渲染帧、屏幕像素、鼠标位置或浏览器可见性；只读取固定步长模拟状态。
10. **玩家可解释**：每次精英/Boss 主动都产生技能开始、解析或取消事件，并在界面显示名称、目标和剩余准备时间。

## 6. 五波小怪 + Boss 编队模板

每关继续使用 `WaveSystem` 的五个小怪遭遇和一个 Boss 遭遇。当前数量 `3 / 4 / 5 / 5 / 6`、同屏上限和 `850ms` 波间停顿保持不变；本规格只明确每一波的战术意图。

| 遭遇 | 数量 | 编队模板 | 投放规则 | 设计目的 |
|---|---:|---|---|---|
| 第 1 波：教学 | 3 | 1 个本区域主展示怪 + 2 个 N1/N2 | 不放精英；必出现本关主机制 | 玩家在无压力下看懂职责 |
| 第 2 波：对照 | 4 | 1 个前排/均衡 + 1 个速度或远程 + 2 个补足 | 不同时出现两个高威胁 N3 | 让属性差异与行为差异形成对比 |
| 第 3 波：战术 | 5 | `tacticalAnchors` 选出前排与速度/远程职责 + 3 个本区域怪 | 允许一次相邻区域普通怪客串，概率不超过 15% | 第一次检验阵容对不同职责的处理效率 |
| 第 4 波：精英 | 5 | 1 个本区域精英 + 2 个与其互补的普通怪 + 2 个基础怪 | 精英只在本区域；精英行为不与两个控制怪同场 | 让玩家先识别精英再处理组合 |
| 第 5 波：考试 | 6 | 区域机制怪 2～3 个 + 前排 1～2 个 + 速度/远程 1 个 + 填充怪 | 不新增机制，只组合前四波已教内容 | 检验阵容是否真正理解区域职责 |
| Boss 波 | Boss + 0/1/1/2 随从 | Boss + 本区域核心随从；区域终点可增加 1 名随从 | 随从不取精英；Boss 技能目标优先级独立 | 把区域机制收束为一次招牌战 |

### 6.1 关卡内解锁节奏

- 区域第 1 关：只出现 N1/N2，Boss 主动以最低频率开始。
- 区域第 2 关：加入 N3 或 Boss 的额外状态表现，但不同时加入精英。
- 区域第 3 关：加入本区域精英；第五波才允许精英与功能普通怪组合。
- 区域第 4 关：Boss 使用区域终点强化参数，编队完整；不引入新效果。

当前 `stageInRegion`、`eliteEncounter`、相邻区域客串和 `bossIdForStage` 已能承载这一编排。数据层应把“为什么出现”保留在遭遇模板，不把随机抽取交给行为系统。

## 7. 十章机制递进表

第一章建立护壳、短控和目标选择等基础词汇；第二章起每章只新增一个主机制，旧机制可以作为低频复习；第十章只做组合和软狂暴，不新增状态。

| 章节 | 区域主机制 | 普通怪职责 | 精英机制 | Boss升级方向 | 允许的主要效果 |
|---:|---|---|---|---|---|
| 1 青丘林地 | 护壳、短慢速、单体短控、后排威胁 | 快攻、前排、后排目标 | 周期减伤、短控、护盾 | 范围慢速/护甲型强化/低血加速 | slow、stun、damageReduction、haste、shield |
| 2 霜风谷 | 霜缓与减速目标易伤 | 远程霜击、减速、高生命前排 | 冻结前置条件 | 减速场、低血霜爆 | slow、vulnerability |
| 3 赤沙荒地 | 冲锋与破甲 | 首击强化、破甲标记 | 破甲后重击 | 破甲范围攻击 | armorBreak、slow |

## 9. Boss 复用、区域终点强化与未来难度

### 9.1 Boss 复用规则

`bossIdForStage(stage)` 继续负责章节内 Boss 轮换：普通区域关可轮换章节三只 Boss，第 4/8/12 关使用所属区域 Boss。Boss 的行为配置属于 Boss 内容本体，不因出场关卡复制一份新 ID。

同一 Boss 在不同区域关卡只改变：

- 关卡数值成长（现有 stage 曲线）；
- 随从数量和本区域随从池；
- 是否启用区域终点强化；
- 难度档位解锁的技能槽。

不能改变 Boss 的目标规则、基础伤害元素或技能名称来制造“同名不同怪”。

### 9.2 区域终点强化

当 `stageInRegion === 3` 时，给 Boss 应用一次 `finale` 修正，不修改 `EnemyDefinition`：

| 项目 | 普通区域关 | 区域终点 |
|---|---:|---:|
| 主动首次冷却 | 5000～5500ms | 减少 10%，不低于 4500ms |
| 主动准备时间 | 800～900ms | 保持不变 |
| 阶段被动阈值 | 50% | 保持 50%，不提前到 70% |
| 随从数量 | 0/1/1 | 1/2，最多 2 名 |
| 新效果 | 无 | 无 |

区域终点强化的目的只是提高熟悉机制的密度；不新增技能、不改变目标数量、不提高控制时长。

### 9.2.1 第一章 Boss 阶段阈值裁决

B04、B08、B12 统一使用 **50% 最大生命值** 作为唯一阶段阈值，原因有三点：

1. 五人自动战斗中，50% 能保证玩家在阶段发生前看到完整的一次主动循环，同时又不会把阶段压缩到战斗尾声。
2. 三只 Boss 的区域职责不同：B04 加速、B08 减伤、B12 加速；统一阈值让玩家学会“半血进入第二段”的规则，差异只来自效果，不来自隐藏门槛。
3. 当前实现的通用 Boss 狂暴阈值是 30%，但按 ID 分支附加不同效果；本规格将该分支裁决为移除，改由配置化的 50% 阶段被动驱动，避免 Boss 在 50% 和 30% 连续获得两次强化。

阶段被动是一次性、永久到战斗结束的状态；不会因为治疗回到 50% 以上而撤销，也不会在 30% 再追加第二个阶段。区域终点只缩短主动首次冷却，不改变 50% 阈值。

### 9.3 难度技能位成长

TBH 的 Skeleton King 在 Normal / Nightmare / Hell / Torment 资料页分别记录 2 / 3 / 4 / 5 个技能。这里采用相同的技能位增长逻辑，但将“普攻”排除在 `abilitySlots` 外：

| 难度档 | Boss `abilitySlots` | 内容 | 第一章实现状态 |
|---|---:|---|---|
| Story / Normal | 2 | 招牌主动 + 阶段被动 | P0；B04/B08/B12 完整实现 |
| Challenge / Nightmare | 3 | 新增一个低频防御或随从互动机制 | P1；不改主线普通关 |
| Hell | 4 | 新增第二个主动或第二阶段修正 | P2；单个主动仍有独立冷却 |
| Torment | 5 | 新增第三个主动/被动组合 | P2；只用于高难关卡 |

技能槽解锁规则：

1. 已存在的主动和阶段被动保留，不用新 ID 替换。
2. 新技能优先从同章已教效果中组合，不在高难突然引入沉默、复活或群体眩晕。
3. 每个新增槽位仍受本规格的伤害、控制、护盾和冷却上限约束。
4. 高难度的技能数量增长不能通过减少读条、随机换目标或不可见被动实现。
5. 难度档不改变普通怪的行为数量；普通怪仍最多一个轻行为。

## 10. 数据模型与运行时架构

### 10.1 数据模型

在不修改本阶段源码的前提下，开发阶段应增加独立内容模型，建议命名如下：

```ts
type EnemyBehaviorId =
  | "none"
  | "quick-double"
  | "shell-guard"
  | "moss-slow"
  | "lowest-hp-hunter"
  | "binding-vine"
  | "bark-guard"
  | "root-snare"
  | "echo-shield";

interface EnemyCombatProfile {
  behaviorId: EnemyBehaviorId;
  basicTargetStrategy: TargetStrategy;
  targetLock: "untilDeath";
  active?: EnemyAbilityDefinition;
  phase?: EnemyAbilityDefinition;
  roleTag: "baseline" | "speed" | "frontline" | "control" | "support" | "boss";
}

interface EnemyAbilityDefinition {
  id: string;
  trigger: TriggerDefinition;
  target: TargetDefinition;
  effects: EffectDefinition[];
  prepareMs?: number;
  cooldownMs?: number;
  once?: boolean;
  telemetryId: string;
}
```

实际类型可按项目命名调整，但必须满足：

- `EnemyDefinition` 只引用 `combatProfileId` 或 `behaviorId`，不持有运行时函数。
- `EnemyCombatProfile` 从独立注册表读取；同一行为可供多个怪物复用。
- `EnemyAbilityDefinition` 只描述数据，效果由通用 `EnemyBehaviorSystem` 执行。
- 敌人的移动寻敌和普攻必须共同读取 `basicTargetStrategy`，并共享锁定到死亡的 `targetId`；主动技能的目标快照独立保存。
- 技能名称、图标、颜色、预警时长和命中表现由 `telegraph`/表现数据读取，不写在模拟分支。
- 难度与终点强化使用 `BossDifficultyProfile` 和 `EncounterModifier`，不复制 Boss 定义。

### 10.2 运行时职责

| 模块 | 责任 |
|---|---|
| `EnemyContentRegistry` | 校验行为引用、技能槽、数值边界和章节解锁 |
| `EnemyBehaviorSystem` | 按固定顺序检查触发器、选择目标、开始/取消/解析行为 |
| `TargetingSystem` | 提供稳定策略和排序，不知道具体怪物 ID；移动与普攻使用同一基础目标 |
| `CombatSystem` | 复用现有伤害、护盾、治疗和状态公式 |
| `WaveSystem` | 只负责遇敌编队、区域池、终点强化上下文 |
| `BattleSimulation` | 驱动单位生命周期和事件，不包含怪物技能 `if/else` |
| `BattleEvent` | 复用 `skill:started`、`skill:resolved`、`skill:cancelled`、`status:applied`；必要时增加通用 `behaviorId` 字段 |

### 10.3 反硬编码验收

- `BattleSimulation` 中不得出现 `bossId === "B04"` 这类行为分支。
- 新增一只拥有既有行为的怪物只需要修改内容注册表与敌人引用，不修改模拟器。
- 新增一种数值效果必须新增通用 `EffectDefinition`，不能复制 Boss 方法。
- 运行时日志输出 `sourceId`、`behaviorId`、`abilityId` 和 `targetIds`，便于离线平衡统计。

### 10.4 P0 与后续运行时能力

P0 需要实现配置化执行已有能力：普攻计数、计时、HP 阈值、稳定目标、多目标伤害、slow/stun/haste/damageReduction/shield、现有事件，以及复用现有单位字段的敌方准备状态。`MovementSystem` 必须在任意阵营准备期间停住该单位，`BattleScene` 必须能用敌方技能表现数据绘制读条。

下列属于后续阶段，必须保留明确标记，不阻塞第一章：

- P1：`onAllyHurt`、`lowestHpAllyOrSelf`、第二至四章的破甲、易伤与链式目标接线。
- P2：敌方 periodic damage/heal、召唤、复活、分段护甲/硬直条、复合技能链、反射效果。
- P3：需要新增玩家交互的打断、地面可躲避区域、实时站位技能。

## 11. UI、特效与可读性

### 11.1 敌人识别

- 普通怪：不显示完整技能栏，只在首次触发行为时显示小型职责图标和短提示。
- 精英：血条左侧显示精英菱形标；血条下显示一个行为图标；护盾/减伤值直接显示在血条上。
- Boss：显示 Boss 名称、独立血条、当前阶段标签和当前主动技能读条。
- 图标必须能在 120px 角色尺寸下辨认：速度（双线）、护壳（盾片）、控制（藤结）、护盾（钟环）、后排威胁（翼眼）。

### 11.2 主动技能表现

统一时序：

```text
技能开始事件 → 角色动作/地面预警 → 准备条倒计时 → 命中/状态 → 技能结束
```

- E08 的单体控制使用脚下藤结预警，不做全屏闪烁。
- B04 的风压使用前方扇形边缘；B08 使用两条石痕；B12 使用最多三个圆形目标预警。
- 预警颜色与效果统一：慢速用青绿、减伤用棕灰、护盾用浅蓝、易伤用紫红、眩晕用黄色。
- 动效不能遮挡英雄血条、Boss 血条或关键数值；屏幕震动只用于 Boss 命中，幅度低且可关闭。
- 快进或后台模拟必须保留事件与最终结果，不要求逐帧播放特效。

### 11.3 失败反馈

战斗结束或重试面板可统计最近一次失败的主因：

- `后排承伤过高`：E07 或同类目标策略贡献超过总英雄伤害的 35%。
- `护盾未及时击破`：E12/B08 的护盾吸收量占其有效生命恢复/保护量超过 20%。
- `精英减伤窗口损失`：对 E03/E04/B08 的减伤期间输出占总输出超过 25%。
- `控制链过长`：任一英雄连续控制超过上限，视为系统错误，不作为玩家反馈。

## 12. 平衡指标与验收标准

### 12.1 运行节奏

沿用战斗数值规格的目标：

- 第一章普通小怪单包清场约 8～15 秒；
- 第一章 Boss 约 20～35 秒；
- 第 12 关 Boss 在有若干良品装备时约 20～40 秒；
- 行为效果不应让无装备默认阵容在首次遇见时直接失去操作空间；
- 同一关卡更换前排、治疗或输出后，至少有一个职责怪造成的承伤分布、存活时间或整关通关时间发生可测变化；不以玩家无法手动控制的击杀顺序作为硬指标。

### 12.2 行为贡献

使用 10 个固定且互不相同的种子、3 套代表阵容（标准、双前排、偏治疗）与无装备/良品装备两档样本，共 60 个有效场景各运行一次并记录：

| 指标 | 目标 |
|---|---:|
| 普通怪行为额外直接伤害占其总伤害 | `5%～18%` |
| 普通怪状态造成的等效生存压力 | 不超过该怪直接伤害的 `35%` |
| 精英机制导致的有效伤害/护盾贡献 | `10%～30%` |
| Boss 主动造成的 Boss 战总承伤 | `12%～28%` |
| 单次 Boss 主动击杀满血非坦英雄 | 0 次；除非该英雄严重低于推荐战力 |
| 第一章单体控制导致的连续停行动 | `≤800ms` |
| 选取的确定性复核场景重复触发的行为顺序差异 | 0；同一 seed 必须一致 |

### 12.3 内容验收

- E01～E12、B04/B08/B12 均有明确的 `combatProfileId` 引用；行为模板允许复用，具体主动技能使用稳定 `abilityId`，且无模拟 ID 分支。
- 每个普通怪最多一个轻行为；E01/E05/E09/E11 明确作为无行为基线。
- 每个精英只有一个机制包；E04/E08/E12 不再共享无差别精英减伤。
- 每个第一章 Boss 恰有一个招牌主动和一个阶段被动。
- 所有第一章技能都能用现有状态、护盾、伤害和目标系统表达；P1/P2 能力没有混入 P0 必做项。
- 同一 Boss 在普通关与区域终点复用相同内容 ID，仅叠加终点修正。
- 五波模板仍产生 `3/4/5/5/6` 个小怪，Boss 随从仍不超过 2 名。
- 所有技能都能在自动战斗、离线或后台模拟下完成，不能依赖玩家实时操作。

### 12.4 开发验收用例

1. 固定 `stage=1` 和 seed，E02 第四次成功普攻只追加一次 0.35 倍伤害。
2. E03 首次跨过 50% 生命只获得一次 18% 减伤，状态结束后不会自动重开。
3. E07 入场时在两个英雄血量比例相同的情况下按稳定 ID 锁定目标；移动和普攻均追踪该目标，目标死亡后才重选。
4. E08 第五次成功普攻只眩晕一个前排英雄 600ms，不产生群体控制。
5. E12 护盾存在期间不叠加第二个护盾，护盾值按实际吸收递减。
6. B04/B08/B12 技能均产生开始、解析和目标列表事件；目标死亡时不随机转移。
7. 三只 Boss 在 50% 生命首次跨阈值时只触发一次阶段被动。
8. 第 4、8、12 关 Boss 只应用终点修正，不改变 Boss ID 或能力数量。
9. 从 60 个平衡场景中选 3 个代表场景各重跑一次，事件序列必须完全一致。
10. 从配置中新增一个复用 `shell-guard` 的测试敌人，不修改 `BattleSimulation` 即可运行。

## 13. 分阶段实施任务

### P0：第一章垂直切片

目标是让玩家在第一章完整感受到“基础属性 + 一个职责行为 + 精英机制 + Boss 主动/阶段”的差异。

1. 建立 `EnemyCombatProfile`、触发器、目标策略和效果的内容类型。
2. 把 E01～E12、B04/B08/B12 的行为移入独立注册表。
3. 实现 `onBasicAttackCount`、`onHpBelow`、`onTimer`、`onEnterCombat`。
4. 抽取稳定目标策略和最多 3 个目标的通用选择器；让敌人的移动和普攻共用配置目标与锁定结果。
5. 接通已有伤害、slow、stun、haste、damageReduction、shield 和事件。
6. 让敌方主动统一支持最少 800ms 的准备表现；准备期间不能普攻，死亡/眩晕可取消。
7. 替换精英通用 `elite-guard`，由 E04/E08/E12 数据分别驱动。
8. 继续使用现有五波生成数量和区域池，按第 6 节补齐锚点规则。
9. 添加事件日志和第一章 10 个开发验收用例。
10. 完成第一章 12 关自动战斗烟雾验证：无装备、良品装备、不同前排/后排组合各一组。

### P1：章节 2～4与可观测性

- 接入第二章霜缓、第三章破甲、第四章雷链；每章只启用本章已声明效果。
- 增加 `onAllyHurt`、破甲/易伤/链式目标接线和敌方行为统计。
- 增加精英职责提示和失败原因摘要。
- 不改变普通怪每只一个行为的预算。

### P2：章节 5～10与高难技能位

- 实现 periodic damage/heal、一次性援护、分段护甲和有限召唤。
- 接入 Normal / Nightmare / Hell / Torment 的 2/3/4/5 `abilitySlots`。
- 每个新增技能先在单章单 Boss 上验证，再推广到章节 Boss 池。
- 高难度只增加技能槽，不取消读条、目标规则和效果上限。

### P3：高级交互（可选）

- 只有当项目明确加入实时操作时，才评估打断、地面躲避区或手动集火。
- 这些能力不属于当前五人自动战斗主线，不能反向成为普通关的通关门槛。

## 14. 对现有文档与实现冲突的裁决

### 14.1 波次结构

普通关采用“五波小怪 + Boss”结构。`WaveSystem.ts` 使用 `TRASH_ENCOUNTERS_BEFORE_BOSS = 5` 和 `ENCOUNTER_COUNTS = [3, 4, 5, 5, 6]`。

### 14.2 旧的统一精英减伤

`BattleSimulation` 当前按所有精英统一第 4 次普攻获得 `damageReduction 20% / 2 秒`。本规格裁决为：保留 E04 的数值语义作为树皮守护，E08 改为单体根缚，E12 改为周期护盾；通用 `elite-guard` 不再作为默认行为。

### 14.3 Boss ID 分支

现有 `castBossSkill` 中按 `B04/B08/B12/B16...` 分支的写法只能作为迁移前兼容依据，正式实现必须改为配置驱动。Boss 技能名称、目标数和倍率进入注册表；模拟器只执行通用行为。

### 14.4 Boss 轮换与美术文档

第一章怪物美术规格规定区域终点使用所属区域 Boss，同时允许普通关轮换三只 Boss；`bossIdForStage` 已按 `stageInRegion` 实现这一轮换。本规格保留该规则，区域终点通过 `finale` 修正强化，不创建新 Boss ID 或换色变体。

### 14.5 数值公式与角色克制

现有战斗数值规格规定敌人 HP、攻击、防御按关卡成长，伤害使用软护甲；本规格不改公式。机制只改变攻击时机、目标和现有状态，不引入额外抗性或必须驱散的负面效果，确保当前五人阵容和英雄技能仍有合理克制路径。
