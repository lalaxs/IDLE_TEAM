## 0. 权威性与废止说明

本文件记录当前已经确定的游戏框架，并取代以下旧方向：

- 废止“26 种族 × 两种性别基础板 + 40 专精装备板”的 92 张模块化美术方案。
- 不再按照《魔兽世界》的完整职业、专精、种族组合生产素材。
- 正式英雄美术改为“一名英雄对应一张完整角色单图”，每名英雄直接设计身份、外形、武器和技能。
- 首发种族与职业数量主动精简，不追求组合穷举。
- 当前阶段不生产正式角色美术，先使用代码原生 SVG 作为背景、英雄、敌人、道具与特效占位图。
- 当前第一优先级是搭建可持续运行的核心玩法，而不是继续深化美术设定。

若旧文档与本文件冲突，一律以本文件为准。

## 1. 产品定义

### 1.1 游戏类型

- 单机 H5 放置 RPG。
- 竖屏移动端优先，桌面浏览器以居中的手机比例运行。
- 五名英雄组成自由小队，战斗始终实时自动进行。
- 第一阶段使用横向自动推进的 2D 战斗表现。
- 后续支持离线挂机，但第一阶段只建立数据边界，不实现完整离线结算。

### 1.2 核心体验

玩家主要完成四件事：

1. 观察五名英雄持续自动战斗；
2. 从战斗中获得装备和金币；
3. 调整五人阵容、英雄装备与成长；
4. 挑战并推进章节和关卡。

游戏不要求传统“坦克、治疗、输出”的固定编成。玩家可以配置五名近战、五名远程、无治疗队或其他任意组合。英雄的攻击距离、移动速度、目标策略与技能自然形成战场站位。

### 1.3 成功标准

第一版可玩原型必须做到：

- 打开页面后 3 秒内进入自动战斗；
- 五名英雄可以自动移动、寻敌、攻击和死亡；
- 不同攻击距离能够明显产生不同站位；
- 每关包含小怪波次和一个 Boss；
- Boss 胜利自动进入下一关；
- 全队失败后自动重置并重复当前关；
- 敌人掉落的物品直接进入当前背包；
- 点击五人姓名血条可以编辑阵容；
- 战斗、阵容、背包和关卡状态可以保存在本地；
- 临时 SVG 美术在 80–120 px 高度下仍然容易辨识。

## 2. 当前非目标

第一阶段明确不实现：

- 完整离线收益结算；
- 联网、登录、云存档、排行榜或社交；
- 支付、广告或正式商业化接口；
- 完整商店经济；
- 正式抽卡概率、保底与付费资源；
- 公会、任务、成就、竞技场、副本组队；
- 《魔兽世界》的完整职业、专精和种族矩阵；
- 92 张模块化角色或装备设定图；
- 正式角色 PNG、骨骼动画或序列帧动画；
- 复杂地图寻路、物理碰撞或多层地形；
- 音频与配音。

## 3. 技术方案

### 3.1 固定技术栈

- 构建工具：Vite；
- 语言：TypeScript，开启严格模式；
- 战场渲染：Phaser 3；
- 文本密集 UI：原生 DOM + CSS；
- 测试：Vitest；
- 浏览器端端到端检查：Playwright 或浏览器游戏试玩工具；
- 存档：`localStorage`；
- 临时美术：独立 SVG 文件或内联 SVG，不使用图片生成模型。

不引入 React。当前项目规模下，Phaser 负责战场、原生 DOM 负责页面和弹窗，可以减少状态同步层级和依赖数量。

### 3.2 核心架构原则

战斗模拟、渲染、UI 与持久化必须分离：

```text
静态数据 ───────┐
                ▼
玩家输入 ──> 游戏状态仓库 ──> 战斗模拟 ──> 游戏事件
                    │             │           │
                    │             ▼           ▼
                    ├──────> Phaser 战场 <── 动画反馈
                    │
                    ├──────> DOM UI
                    │
                    └──────> localStorage
```

- 战斗规则不能写进 Phaser 精灵回调。
- Phaser 精灵不能成为血量、进度或背包的唯一数据源。
- DOM UI 只派发意图，例如“替换 3 号位英雄”，不直接修改多个系统。
- 存档只保存可序列化状态，不保存场景、精灵、计时器或 DOM 引用。

## 4. 主循环

```text
进入当前关卡
  ↓
生成第 1 波小怪
  ↓
五名英雄自动移动并战斗
  ↓
击败敌人 → 金币与装备直接入背包
  ↓
第 2 波小怪
  ↓
Boss 波
  ├─ 胜利 → 结算 Boss 奖励 → 进入下一关
  └─ 失败 → 显示短暂失败反馈 → 重置并重复当前关
```

### 4.1 每关结构

- 每个普通关卡包含 3 波：
  1. 第一波：3–5 名普通敌人；
  2. 第二波：4–7 名普通敌人，可混入 1 名精英；
  3. 第三波：1 名 Boss + 0–3 名随从。
- 同屏敌人上限暂定 10 名。
- 每波清空后等待 0.8 秒生成下一波。
- Boss 死亡后等待 1.2 秒进入下一关。
- 所有英雄死亡即判定失败。
- 失败反馈持续 1.5 秒，然后恢复小队并从当前关第 1 波重新开始。
- 失败不扣装备、金币或章节进度。

### 4.2 连续战斗

- 切换“背包、商店、英雄、关卡”底部页签时，战斗不暂停。
- 打开半屏英雄选择抽屉时，战斗不暂停。
- 打开全屏召唤页时，第一阶段允许战斗继续模拟，但暂停战场声音和强动效。
- 浏览器标签进入后台时，记录 `lastActiveAt`，不继续依赖浏览器计时器模拟战斗。
- 只有显式调试暂停和浏览器不可用状态可以停止模拟。

## 5. 战斗模拟

### 5.1 时间模型

- 模拟固定步长：每秒 20 次，即 `50 ms` 一次；
- 渲染目标：每秒 60 帧；
- 每帧累计时间，按固定步长执行模拟；
- 单帧最多补算 5 次，避免后台恢复时发生“死亡螺旋”；
- 渲染只插值位置，不改变战斗结果。

### 5.2 战场坐标

- 逻辑战场宽度：`1000` 单位；
- 英雄出生区域：`x = 90–190`；
- 敌人出生区域：`x = 810–940`；
- 英雄面向右，敌人面向左；
- 使用一条主要横向战线，附加少量 `y` 偏移避免完全重叠；
- `y` 偏移只影响显示顺序，不形成独立可寻路的战斗路线。

### 5.3 单位数据

```ts
type UnitState = {
  id: string;
  team: "heroes" | "enemies";
  sourceId: string;
  x: number;
  y: number;
  hp: number;
  maxHp: number;
  attack: number;
  defense: number;
  attackRange: number;
  moveSpeed: number;
  attackIntervalMs: number;
  attackCooldownMs: number;
  skillCooldownMs: number;
  targetId: string | null;
  alive: boolean;
};
```

### 5.4 攻击距离

攻击距离是角色自然站位的唯一主要依据，不定义前排和后排：

| 距离类型 | 范围 | 典型角色 |
|---|---:|---|
| 近程 | 55–75 | 战士、狂战、刺客 |
| 中程 | 130–170 | 萨满、短杖辅助 |
| 远程 | 240–300 | 弓手、法师、牧师 |

目标距离大于攻击距离时向目标移动；进入攻击距离后停止前进并攻击。目标死亡、失效或距离异常时重新选择目标。

### 5.5 目标选择

第一阶段固定三种目标策略：

- `nearestEnemy`：攻击距离最近的存活敌人；
- `lowestHpEnemy`：攻击百分比生命最低的敌人；
- `lowestHpAlly`：为百分比生命最低且未满血的友军提供治疗。

默认英雄和敌人使用 `nearestEnemy`。刺客可以使用 `lowestHpEnemy`，治疗技能使用 `lowestHpAlly`。队伍不配置治疗英雄时，系统不提供额外强制治疗。

### 5.6 基础伤害

```text
rawDamage = attack - defense × 0.55
finalDamage = max(1, round(rawDamage × random(0.92, 1.08)))
criticalDamage = round(finalDamage × 1.5)
```

- 默认暴击率 5%；
- 临时原型不加入命中、闪避、元素抗性和复杂异常状态；
- 治疗量不受敌人防御影响；
- 所有随机数必须通过可注入的随机源，单元测试使用固定种子。

### 5.7 空间规则

- 单位之间保留最小横向间距 24；
- 友方允许轻微重叠，敌我不能完全穿透；
- 近战单位到达目标后按 `y` 偏移排列；
- 远程单位只要进入攻击距离即可停下；
- 不实现复杂阻挡、绕路和推挤物理。

## 6. 关卡与成长

### 6.1 章节结构

- 每章 12 个关卡；
- 每关均有 Boss；
- `1-12` 通关后解锁第 2 章；
- 章节页面使用网格卡片，不使用曲线路径地图；
- 每张章节卡显示章节名称、完成进度、推荐战力和锁定条件。

首发原型提供两章：

1. 第一章：青丘边境；
2. 第二章：赤沙古道。

第二章可以只提供数据和锁定卡片，第一阶段至少完整实现第一章 12 关。

### 6.2 数值成长

敌人数值按关卡递增：

```text
stagePower = 1.16 ^ (globalStageIndex - 1)
enemyHp = round(baseHp × stagePower)
enemyAttack = round(baseAttack × stagePower ^ 0.82)
enemyDefense = round(baseDefense × stagePower ^ 0.72)
```

Boss 额外规则：

- 生命值乘 `5.0`；
- 攻击力乘 `1.35`；
- 体型为普通敌人的 `1.45–1.7` 倍；
- 掉落至少一件装备。

### 6.3 战力

战力只用于比较与 UI 提示，不直接参与伤害：

```text
heroPower =
  maxHp × 0.10 +
  attack × 3.0 +
  defense × 2.0 +
  1000 / attackIntervalMs × attack × 0.8
```

队伍战力等于五名上阵英雄战力之和。

## 7. 英雄框架

### 7.1 简化原则

- 不建立“种族 × 职业 × 性别”的组合矩阵。
- 每名英雄直接拥有固定身份和完整单图。
- 种族、职业和性别只作为角色元数据与叙事标签。
- 首发只使用 3 个原创种族方向与 6 个职业方向。
- 同一职业允许出现不同攻击距离、武器或技能的具体英雄。

### 7.2 首发种族

| 种族 | 视觉方向 | 玩法影响 |
|---|---|---|
| 王国人 | 圆脸、普通耳型、暖肤色 | 无种族数值加成 |
| 森灵 | 长耳、叶片或木质特征 | 无种族数值加成 |
| 兽裔 | 圆形兽耳、短尾或角 | 无种族数值加成 |

种族第一阶段只影响外观，不加入种族天赋。

### 7.3 首发职业方向

| 职业 | 主要距离 | 核心识别 |
|---|---|---|
| 战士 | 近程 | 剑、斧、盾与高生命 |
| 游侠 | 远程 | 弓、投射物与稳定输出 |
| 法师 | 远程 | 法杖、范围伤害与低防御 |
| 牧师 | 远程 | 治疗、护盾与低伤害 |
| 刺客 | 近程 | 双匕首、低血目标优先 |
| 萨满 | 中程 | 图腾、连锁攻击或辅助 |

### 7.4 首发英雄

原型提供 8 名英雄，初始解锁 6 名，队伍固定上阵 5 名：

| ID | 名称 | 种族 | 职业 | 距离 | 核心能力 | 初始状态 |
|---|---|---|---|---|---|---|
| H01 | 洛恩 | 王国人 | 战士 | 65 | 盾击，小范围眩晕 | 已解锁、默认上阵 |
| H02 | 布兰 | 王国人 | 战士 | 60 | 双持连击，低血增伤 | 已解锁、默认上阵 |
| H03 | 米娅 | 王国人 | 法师 | 270 | 火球爆炸，范围伤害 | 已解锁、默认上阵 |
| H04 | 诺拉 | 森灵 | 牧师 | 250 | 治疗百分比最低的友军 | 已解锁、默认上阵 |
| H05 | 塔林 | 森灵 | 游侠 | 290 | 稳定远程连射 | 已解锁、默认上阵 |
| H06 | 乌鸦 | 兽裔 | 刺客 | 55 | 优先攻击低血敌人 | 已解锁 |
| H07 | 塞拉 | 森灵 | 法师 | 250 | 冰霜减速 | 未解锁 |
| H08 | 海泽 | 兽裔 | 萨满 | 150 | 连锁闪电或小型图腾 | 未解锁 |

默认上阵为 H01–H05。玩家可以移除牧师、战士或任意角色，不做队伍合法性限制。

## 8. 装备与掉落

### 8.1 背包

- 初始容量 40 格；
- 敌人掉落自动进入背包；
- “战利品”页签显示整个当前背包，而不是最近掉落列表；
- 最近获得的物品只以短暂 toast 提示，不建立独立战利品队列；
- 背包满时，普通品质物品自动换算为金币；更高品质进入临时溢出队列，最多 10 件。

### 8.2 装备位

第一阶段每名英雄只有 3 个装备位：

1. 武器；
2. 护甲；
3. 饰品。

装备只提供以下基础属性：

- `attack`；
- `maxHp`；
- `defense`；
- `attackSpeed`。

不实现套装、宝石、强化失败、耐久和职业限制。

### 8.3 品质

| 品质 | 颜色 | 属性倍率 |
|---|---|---:|
| 普通 | 灰棕 | 1.00 |
| 优良 | 绿色 | 1.25 |
| 稀有 | 蓝色 | 1.60 |
| 史诗 | 紫色 | 2.10 |

Boss 至少掉落一件装备，品质根据关卡提升。原型不加入传奇品质。

## 9. 页面与交互

### 9.1 基准尺寸

- 设计基准：`390 × 844`；
- 移动端铺满安全区域；
- 桌面端最大宽度 `430 px`，居中显示；
- 战场使用 Phaser Canvas；
- 顶栏、姓名血条、下方面板、导航和弹窗使用 DOM。

### 9.2 战斗首页

从上到下：

1. 顶部状态栏；
2. 战斗区域；
3. 五人姓名血条；
4. 当前功能面板；
5. 四个底部页签。

顶部状态栏显示：

- 当前章节和关卡；
- 金币；
- 战斗速度 `1× / 2×`；
- 设置入口。

战斗区域显示：

- 横向推进战场；
- 当前波次；
- Boss 名称与 Boss 血条；
- 伤害、治疗跳字；
- 最近掉落 toast；
- 失败重试和过关反馈。

### 9.3 五人姓名血条

- 五个姓名板横向排列；
- 姓名板整块背景就是生命进度，不在卡片内部再放一条细血条；
- 血量从左向右减少；
- 姓名始终覆盖在血量底色之上；
- 可显示等级或技能能量，但不能破坏姓名阅读；
- 点击任意姓名板进入阵容编辑；
- 不在姓名板写“坦克、治疗、前排、后排”。

### 9.4 底部导航

固定四项：

1. 背包；
2. 商店；
3. 英雄；
4. 关卡。

切换页签只替换下方功能面板，战斗区域与姓名血条继续显示并继续模拟。

### 9.5 背包页签

- 默认页签；
- 显示当前背包网格和 `已用 / 容量`；
- 点击装备显示属性与“装备给英雄”入口；
- 提供筛选与整理按钮；
- 不显示“最近战利品列表”。

### 9.6 商店页签

- 第一阶段只搭建位置和基础卡片；
- 显示“商店内容后续开放”；
- 不实现购买、刷新和付费资源。

### 9.7 英雄页签

- 显示已持有英雄的收藏与详情；
- 可以查看等级、装备和基础属性；
- 不在此处编辑上阵位置；
- 阵容编辑仍然从五人姓名血条进入。

### 9.8 关卡页签

- 使用章节网格卡片；
- 卡片显示区域名、进度、推荐战力和锁定条件；
- 点击已解锁章节可以选择其中已解锁关卡；
- 不使用曲线路径或复杂世界地图。

### 9.9 阵容编辑

流程：

```text
点击任意姓名血条
  ↓
进入阵容编辑页，显示 5 个角色位置
  ↓
点击其中一个位置
  ↓
底部弹出半屏英雄选择抽屉
  ↓
选择已持有且已解锁英雄
  ↓
替换该位置并保存
```

规则：

- 阵容固定 5 个位置；
- 同一英雄不能重复上阵；
- 空位置允许临时存在，但保存时至少需要 1 名英雄；
- 位置不代表前排或后排；
- 阵容顺序只影响初始显示偏移，不覆盖英雄的攻击距离行为。

### 9.10 半屏英雄选择抽屉

- 高度约为视口的 50%；
- 只显示持有且已解锁英雄；
- 保留阵容编辑页作为背景上下文；
- 包含“抽取英雄”按钮；
- 点击英雄立即替换当前选中位置；
- 点击遮罩或下拉手柄关闭。

### 9.11 全屏召唤弹窗

- 从半屏英雄选择抽屉点击“抽取英雄”进入；
- 全屏覆盖；
- 有明确关闭按钮；
- 关闭后回到原来的半屏英雄抽屉；
- 第一阶段只实现视觉流程和固定结果演示，不实现正式概率。

## 10. 临时 SVG 美术规范

### 10.1 总体原则

- 所有临时美术必须是代码原生 SVG；
- SVG 是原型占位资产，不是正式美术母版；
- 每个英雄、敌人或背景各自拥有独立 SVG；
- 不使用身体、装备、种族的模块化拼装生产方式；
- 后续正式美术按“一名英雄一张完整单图”替换；
- SVG 文件名和运行时资产键保持稳定，未来只替换文件，不修改业务逻辑。

### 10.2 角色方向

- 角色为朝右的三分之四侧身；
- 敌人朝左，可通过独立 SVG 或受控水平翻转实现；
- 总体为约 `1.45–1.65` 头身；
- 头部占总高 `58%–64%`；
- 无明显脖子；
- 双手为圆形；
- 双脚极短并前后错开；
- 只保留两只黑色椭圆眼睛，不画嘴、鼻子和眉毛；
- 远侧眼睛、手和脚略小或部分遮挡，以形成侧身感。

### 10.3 线条与颜色

- 外轮廓颜色：`#2F2925`；
- 外轮廓宽度：角色头宽的 `9%–12%`；
- 内部线宽：外轮廓的 `45%–60%`；
- 端点和转角全部圆角；
- 单角色使用 `4–6` 个纯色色块；
- 禁止渐变、写实材质、复杂高光和细小纹理；
- 单角色内部主要分隔线不超过 8 条；
- 武器必须可辨认，但不能遮住脸和身体主体。

### 10.4 英雄 SVG

每个英雄 SVG 建议 `viewBox="0 0 128 128"`，必须包含稳定的分组：

```xml
<svg viewBox="0 0 128 128">
  <g id="shadow"></g>
  <g id="back-weapon"></g>
  <g id="body"></g>
  <g id="far-arm"></g>
  <g id="head"></g>
  <g id="near-arm"></g>
  <g id="front-weapon"></g>
</svg>
```

临时动画只变换整个组：

- 待机：上下浮动 `2–3 px`；
- 移动：左右脚和身体轻微交替，周期 `320–420 ms`；
- 攻击：身体向前 `4–8 px` 并回弹；
- 受击：短暂向后 `3–5 px`；
- 死亡：下沉、旋转或淡出；
- 不制作 SVG 骨骼系统。

### 10.5 背景 SVG

首章战场拆成以下稳定资产：

| 资产键 | 内容 |
|---|---|
| `bg_sky_green_border` | 天空与远处云层 |
| `bg_hills_green_border` | 两层圆润远山 |
| `bg_ground_green_border` | 草地、土路与战斗基线 |
| `bg_props_green_border` | 石块、树桩与简化遗迹 |

背景只使用低饱和大色块和粗线条，不放置会干扰角色与跳字的高对比细节。

### 10.6 临时敌人

第一章至少提供：

- 小树怪；
- 蘑菇怪；
- 石甲虫；
- 木桩精英；
- 古树 Boss。

敌人沿用大头、短身、粗线条语言，但可以有一条简化嘴线；英雄仍保持无嘴规范。

### 10.7 临时特效

只使用：

- 圆环；
- 星形；
- 短线；
- 扇形；
- 简化箭矢或法球；
- 伤害与治疗数字。

不制作复杂粒子纹理。特效持续时间控制在 `120–500 ms`。

## 11. UI 视觉规范

### 11.1 风格

- 卡通扁平；
- 深棕粗线条；
- 奶油纸色面板；
- 圆角卡片；
- 颜色明快但不高饱和刺眼；
- 不使用金属写实框、暗黑写实材质或通用 SaaS 面板风格。

### 11.2 主题变量

:root {

### 11.3 动效

## 12. 状态与存档

### 12.1 持久状态

```ts
type SaveDataV1 = {
  version: 1;
  updatedAt: number;
  lastActiveAt: number;
  currentChapter: number;
  currentStage: number;
  highestUnlockedStage: number;
  gold: number;
  gems: number;
  roster: Record<string, HeroProgress>;
  party: [string | null, string | null, string | null, string | null, string | null];
  inventory: InventoryItem[];
  settings: {
    battleSpeed: 1 | 2;
    reducedMotion: boolean;
  };
};
```

### 12.2 不保存的状态

- 当前精灵对象；
- Phaser 场景；
- DOM 节点；
- 正在播放的动画；
- 单次跳字；
- 粒子；
- 当前波次中的精确敌人位置。

重新加载页面时从当前关第 1 波开始，不恢复半场战斗。

### 12.3 保存时机

- 关卡胜利；
- 关卡失败重置；
- 阵容变化；
- 装备变化；
- 背包变化；
- 设置变化；
- 页面隐藏或关闭前。

存档键固定为：

```text
idle-rpg-save-v1
```

## 13. 事件接口

模拟层至少发出：

```ts
type GameEvent =
  | { type: "unit:moved"; unitId: string; x: number; y: number }
  | { type: "unit:attacked"; sourceId: string; targetId: string }
  | { type: "unit:damaged"; unitId: string; amount: number; critical: boolean }
  | { type: "unit:healed"; unitId: string; amount: number }
  | { type: "unit:died"; unitId: string }
  | { type: "wave:started"; waveIndex: number }
  | { type: "wave:cleared"; waveIndex: number }
  | { type: "stage:won"; chapter: number; stage: number }
  | { type: "stage:lost"; chapter: number; stage: number }
  | { type: "loot:added"; itemId: string }
  | { type: "party:changed"; party: SaveDataV1["party"] };
```

渲染器和 UI 订阅事件，不反向拥有战斗状态。

## 14. 调试与性能

### 14.1 调试模式

访问参数 `?debug=1` 时显示：

- 模拟 FPS 与渲染 FPS；
- 单位逻辑坐标；
- 攻击距离线；
- 当前目标 ID；
- 当前波次；
- 随机种子；
- 手动“下一波、击杀敌人、击杀全队、增加掉落”按钮。

### 14.2 性能预算

- 同屏单位不超过 15；
- 同屏跳字不超过 20；
- 同屏临时特效不超过 25；
- 移动端目标 60 FPS；
- 模拟耗时目标低于每步 `3 ms`；
- SVG 不包含滤镜、模糊、蒙版动画或超过 80 个可见节点；
- DOM 常驻覆盖面积不超过屏幕的 52%，战场中央不放大型弹窗。

## 15. 测试要求

### 15.1 模拟单元测试

必须覆盖：

- 近战英雄会继续移动直到进入近程；
- 远程英雄在远处停下并攻击；
- 不同距离英雄不会被强制排成固定前后排；
- 目标死亡后可以重新选敌；
- 全队死亡触发 `stage:lost`；
- 失败后仍然保持当前关卡；
- Boss 死亡触发 `stage:won`；
- 胜利后关卡加一；
- 治疗英雄缺席时战斗仍可正常运行；
- 五名相同距离英雄可以组成合法队伍；
- 固定随机种子得到一致结果。

### 15.2 存档测试

- 新玩家可以生成默认存档；
- 非法或旧版本存档可以迁移或回退；
- 阵容不允许重复英雄；
- 存档中不存在的英雄 ID 会被移除；
- 背包容量和溢出逻辑正确；
- 重新加载从当前关第 1 波开始。

### 15.3 浏览器试玩

至少验证：

- 390 × 844；
- 430 × 932；
- 桌面 1440 × 900；
- 战斗加载后自动运行；
- 四个底部页签均可切换；
- 姓名血条可进入阵容编辑；
- 半屏英雄抽屉高度正确；
- 全屏召唤页能关闭并返回抽屉；
- Boss 胜负循环可以连续运行三关；
- 背包掉落立即出现；
- 2× 战斗速度不破坏模拟。

## 17. Agent 执行规则

任何继续制作的 Agent 必须遵守：

1. 先阅读本文件，再阅读具体实施计划。
2. 不恢复 92 张模块化美术方案。
3. 不把种族和职业重新扩张成全组合矩阵。
4. 不在第一阶段实现非目标功能。
5. 战斗规则只写在模拟层。
6. Phaser 只负责战场显示和输入桥接。
7. DOM 负责文字、列表、姓名血条、页面、抽屉和弹窗。
8. 所有临时角色使用独立完整 SVG，不做身体与装备拼装。
9. 角色必须朝右侧身，极 Q、粗线条、低细节。
10. 不预设前排、后排或强制职业组合。
11. 每完成一个里程碑必须运行对应测试和浏览器试玩。
12. 不覆盖已存在的用户文件；新增资产必须使用稳定 ID 和版本号。
