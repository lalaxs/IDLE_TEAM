# 横版战斗背景 · 美术需求总表

> 用途：优化 / 重做游戏中不同场景的横版战斗背景时，作为统一需求入口。  
> 整理日期：2026-08-31  
> 运行时资源：`public/assets/backgrounds/`（已接入）  
> 原始设计与清单见文末「参考文档」。

> 已跑通的分层背景、纯色底去边与单体前景流程见：`docs/art/workflows/layered-background-asset-workflow.md`。

## 1. 使用与技术规格

| 项 | 说明 |
|---|---|
| 用途 | 主线战斗横版分层区域地图 + 区域共用前景遮挡层 |
| 运行时尺寸 | **860 × 484**（约 16:9 横版），WebP |
| 运行时路径 | 关卡：`public/assets/backgrounds/stages/stage_{章}_{关}.webp` |
| 前景路径 | `public/assets/backgrounds/foreground/fg_{章}_{区域}.webp` |
| 映射逻辑 | `src/content/battleBackgrounds.ts` → `getBattleBackgroundKeys(stage)` |
| 章节复用 | **第 5～10 章视觉复用第 1～4 章**资源（`visualChapter`），暂无独立背景 |
| 战斗安全区 | 画面**中央约 58% 宽度**低对比、无大地标，供角色与敌人站位 |
| 视觉语言 | 厚描边童话：暖黑粗圆轮廓、低饱和平涂、圆润剪影；每物体最多一块硬边暗面 |
| 禁止 | 文字 / 水印 / UI 节点 / 关卡编号 / 写实纹理 / 电影式光影 |

### 1.1 图层约定

| 层 | 内容 | 备注 |
|---|---|---|
| 分层区域地图 | 天空 + 远景 + 后缘 + 道路 | 每章最多 3 套，每套覆盖连续 4 关 |
| 前景遮挡 | 模块化透明 PNG/WebP | 同章可跨区域复用，程序随机组合 |
| DOM / 角色 | 英雄、敌人、跳字、技能 | 叠在母图之上；前景可略遮脚部草叶 |

### 1.2 每章交付结构（美术侧）

每章上限：

- **3 套**区域分层地图（按关卡 4+4+4 复用）
- **1 张**章节地图横版（无 UI、无节点数字）
- 一组可跨区域复用的模块化透明前景

同一区域的 4 关不再更换背景构图。demo 阶段不增加逐关地标变体、背景兼容层或存档迁移。

## 1.3 目标形态：无缝横版卷轴（首尾相连）

> 现状：每关一张 **860×484** 单屏定帧，镜头只做极小视差位移（约 ±40 px），**不是**可循环长卷。  
> 目标：改成「一条很长的横版场景」，程序横向滚动，**左缘与右缘无缝相接**，可无限循环。

### A. 尺寸怎么定（推荐写进出图 brief）

以战斗画布为基准：

| 基准 | 数值 | 来源 |
|---|---|---|
| 逻辑视口宽 `W` | **430** | Phaser 战斗宽 |
| 逻辑视口高 `H` | **280** | Phaser 战斗高 |
| 美术母图高 | **560**（= 2×H）或沿用 **484** | 2× 便于清晰缩放；484 兼容旧资源 |
| 美术母图宽 | **`N × W_art`** | 必须是「一屏宽度」的整数倍，便于循环取模 |

推荐两档（二选一，全项目统一）：

| 档位 | 母图尺寸 | 含义 | 适用 |
|---|---|---|---|
| **标准卷** | **2580 × 484** | 宽 = 3 × 860；高同现网 | 改动小、与现导出脚本接近 |
| **高清卷（首选）** | **3440 × 560** | 宽 = 8 × 430；高 = 2 × 280 | 循环更长、少重复感；按视口整数倍最干净 |

规则口诀：

1. **高度**固定，对齐战斗区纵横比（约 1.5～1.8 宽高比的「一屏切片」）。  
2. **宽度** = `循环圈数 N × 一屏宽`，`N ≥ 3`（少于 3 圈，走路很快看出重复）。  
3. 运行时可用 `tileSprite` / 双图首尾拼接，按 `scrollX % loopWidth` 滚动。  
4. 导出 WebP 时**不要裁成单屏**；保留整条长卷。

### B. 「首尾相连」美术硬性要求

| 项 | 要求 |
|---|---|
| 接缝 | 左缘第 1 列像素与右缘最后 1 列在**颜色、地平线高度、道路宽、草密度**上连续；建议左右各留 **64～128 px** 重叠校验带 |
| 地平线 | 整卷同一条水平基线（脚底地面高度固定），禁止起伏过大导致角色「爬山」 |
| 道路 / 地面带 | 中下部连续可走带，高度范围固定（建议占画高 **35%～55%** 为地面带） |
| 独特地标 | 大树、桥、祭坛等**禁止压在接缝上**；接缝处只用可重复元素（草、石、云、矮丛） |
| 天空 | 可平涂或极缓渐变；云团不要只在一侧出现一块「签名云」 |
| 禁止 | 单向光影强对比（一侧大亮一侧大暗）、单向透视灭点、无法循环的河流「源头→尽头」 |

**出图自检：** 把图复制两份左右拼成 `2W`，在接缝处放大看是否有断线、跳色、地平线错位。

### C. 分层建议（卷轴 + 视差）

一条「一体长卷」能做循环，但观感一般。更优是 **2～3 层同高、不同循环宽** 的无缝条：

| 层 | 内容 | 建议循环宽 | 滚动速度 |
|---|---|---|---|
| Far | 天空 + 远山 | `2～3` 屏 | 最慢（约 0.2～0.4×） |
| Mid | 中景树石 / 建筑剪影 | `3～4` 屏 | 中速（约 0.6～0.8×） |
| Near | 地面道路 + 近景草 | `3～4` 屏 | 与镜头接近（1.0×） |
| FG | 透明遮挡草叶（可选） | 与 Near 同宽 | 略快（1.1～1.2×） |

同层内仍须首尾无缝；**不同层循环宽可以不同**，避免所有层同一节奏重复。

### D. 与「关卡辨识」怎么共存

现行分层方案：

- **按区域**出卷（每章 3 卷：如草地卷 / 森林卷 / 遗迹卷），同区域 4 关共用一条循环卷；  
- 区域辨识由道路、远景和后缘层完成；天空和模块化前景允许同章复用；
- demo 阶段不为单关添加调色、天气或独立地标配置，避免重新形成 12 套隐性变体。

### E. 给美术的一句话 brief（可直接贴）

```text
输出一张可左右无缝平铺的横版战斗卷轴。
尺寸：3440×560（宽=8×430 视口，高=2×280）。
风格：厚描边童话，低饱和平涂。
地面带高度全程一致；左右边缘无缝衔接（用两份横拼检查接缝）。
大形地标远离左右边缘至少 200px；接缝处仅重复性植被/碎石。
无文字、无 UI、无单侧强光。中央高度 40%–55% 为可站立地面带。
```

### F. 程序侧后续（接入时）

现网 `BattleScene` 用单张 `image` + cover 缩放，需改为例如：

- `tileSprite` 或双 `image` 首尾相接；  
- `scrollX = cameraWorldX * parallaxFactor`；  
- `loopWidth = texture.width`（纹理已是完整一圈）。

尺寸约定稳定后，再同步导出脚本与 `src/assets/manifest.ts`。

## 7. 前景遮挡层验收要点（优化时必守）

对每张 `fg_*.webp`：

1. 与对应章母图**同画幅比例**（运行时随场景缩放）。
2. 顶部两角 alpha ≈ 0；中上部大面积透明。
3. 中央横向 **38%～62%** 内，alpha > 16 的像素占比 ≤ **0.1%**，且只能出现在最底部约 **36 px**。
4. 色键生产背景为纯 `#ff00ff`（历史流程）；成品不得有明显品红残边。
5. 叠在角色上方时，中央交战区仍清晰可读。

## 8. 优化工作建议清单

按优先级建议：

1. **先定卷轴规格：** 采用上文 **1.3**（推荐 **3440×560** 高清卷或 **2580×484** 兼容卷），全项目统一一档。  
2. **按章最多 3 套：** 每个区域覆盖连续 4 关，禁止再拆成逐关背景变体。  
3. **共享稳定图层：** 同章天空与通用前景可复用，道路、远景和后缘建立区域差异。  
4. **第四章叙事对齐：** 「雷崖高地」vs「云岚天境」是否改主题或改章节文案。  
5. **第 5～10 章：** 目前复用 1～4；独立场景时按「每章 3 条循环卷 + 3 前景」扩展。  
6. **导出：** 长卷保留全宽 WebP；文件名可改为如 `scroll_01_meadow.webp`，并更新 `src/assets/manifest.ts` 与背景资源映射。
